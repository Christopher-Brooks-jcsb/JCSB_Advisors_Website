\# JCSB Wealth Management — Web Design Guide ### Medium-Specific Reference for All Web & Digital Work *Last updated: March 2026 — Internal Use Only* --- ## How This Document Works This guide covers everything specific to web and digital contexts. It **extends** the Brand Foundation (`01_JCSB_Brand_Foundation`) — it does not redefine colors, typefaces, or brand philosophy. Load the Brand Foundation first, then this guide. **Use this guide for:** Website pages, landing pages, digital ads, email templates, web-rendered HTML documents, and any interactive or screen-rendered output. The core rule that separates web from print: **web is a living medium and print is a static one.** Web design can and should use depth, motion, layering, and interactive states. These are not anti-patterns on web — they are the language of the medium. Many elements explicitly avoided in print are actively encouraged here. --- ## 1. What Web Gets That Print Doesn't These are features, not compromises. Use them with intention. ### Gradients Gradients are a first-class tool on web. They create depth, atmosphere, and visual interest that flat color cannot. **Approved gradient patterns:** **Hero mesh gradient** — two radial gradients layered on a dark background: ```css background:  radial-gradient(ellipse 60% 70% at 80% 50%, rgba(62,142,99,0.18) 0%, transparent 65%),  radial-gradient(ellipse 40% 50% at 10% 80%, rgba(81,119,153,0.15) 0%, transparent 60%); ``` **CTA block gradient** — directional dark gradient for large CTA panels: ```css background: linear-gradient(135deg, var(--blue-dark) 0%, #1a2d36 100%); ``` **Credit/stat card gradient** — deep green gradient for highlight cards: ```css background: linear-gradient(135deg, #1a3a28, #2a5040); ``` **Photo/placeholder gradient** — soft two-tone for image placeholders and section fills: ```css background: linear-gradient(145deg, var(--green-subtle), var(--blue-pale)); ``` **Progress bar fill:** ```css background: linear-gradient(90deg, var(--green), var(--green-light)); ``` **Rules:** - Gradients always use brand tokens as source colors — no arbitrary hex values - Radial gradients on dark backgrounds use low opacity (0.12–0.25) — they are atmosphere, not color fields - Never use gradients on body text backgrounds — they reduce readability ### Cards Cards are the primary content unit on web. On web they provide appropriate visual chunking, hover feedback, and scannable structure. **Dark glass card** (used on dark backgrounds): ```css background: rgba(255,255,255,0.04); border: 1px solid rgba(255,255,255,0.09); border-radius: 12–16px; backdrop-filter: blur(12px); ``` **White card on pale background** (philosophy pillars, service cards): ```css background: white; border-radius: 12px; border: 1px solid rgba(62,142,99,0.15); padding: 28px; transition: box-shadow .2s, transform .2s; ``` Hover: `box-shadow: 0 8px 32px rgba(62,142,99,0.12); transform: translateX(4px);` **Floating hero card** (live data or key metric display): ```css border-radius: 16px; padding: 36px; animation: floatCard 6s ease-in-out infinite; ``` `@keyframes floatCard { 0%, 100% { transform: translateY(0); } 50% { transform: translateY(-8px); } }` **Card rules:** - Cards on dark backgrounds: always use the glass pattern — never solid white on dark - Cards on light backgrounds: white + green border pattern - Hover transforms are small and directional: `translateY(-2px)` for vertical, `translateX(4px)` for horizontal list items - `border-radius` on cards: 12–16px. Never 4px (too sharp) or 24px+ (too rounded for financial credibility) - `border-radius: 100px` is permitted for pill-shaped badges and chips only ### Box Shadows Box shadows signal elevation and layering — appropriate and expected on web. **Shadow scale:** - Subtle (resting state): `0 2px 8px rgba(0,0,0,0.08)` - Standard (card hover): `0 8px 32px rgba(62,142,99,0.12)` - Deep (modals, overlays): `0 24px 80px rgba(0,0,0,0.35)` - Navigation: `0 2px 12px rgba(0,0,0,0.3)` Never use pure black shadows — always tint toward `--blue-dark` or `--green`. ### Animations and Transitions Use motion to guide attention and provide feedback, not for decoration. **Approved animation patterns:** - **Scroll reveal:** `opacity: 0; transform: translateY(28px)` → `.visible { opacity: 1; transform: translateY(0); }` — `transition: .65s ease` - **Hover lift:** `transform: translateY(-2px)` — `transition: .2s` - **Hover slide:** `transform: translateX(4px)` — `transition: .2s` - **Pulse dot:** `@keyframes pulse { 0%, 100% { opacity: 1; } 50% { opacity: .4; } }` — for live/active indicators - **Float card:** 6s infinite ease-in-out, 8px vertical travel — for hero display cards only - **Progress bar fill:** `transition: width 1s ease` — triggered on scroll into view **Rules:** - All transitions: `.2s` for hover states, `.65s` for scroll reveals - Never animate color directly — animate opacity or transform instead - No autoplay video, parallax, or scroll-jacking — these hurt readability and credibility ### Backdrop Filter / Blur `backdrop-filter: blur(8–12px)` is approved for: - Fixed navigation bar on scroll - Glass cards on dark backgrounds - Modals and overlays Not approved for body section backgrounds — blur should feel intentional, not ambient. --- ## 2. Section Architecture Web pages are built from full-width sections, each with its own background zone. Unlike print's panel system (which bleeds to page edges horizontally), web sections stack vertically and scroll. **Approved section backgrounds (in order of use frequency):** 1. `var(--white)` — primary content sections 2. `var(--blue-pale)` — alternate sections 3. `var(--blue-dark)` — process/steps sections, CTA sections, hero 4. `#1a262c` — footer (slightly deeper than `--blue-dark`) **Alternating pattern:** White → Pale → White → Dark → White is the standard page rhythm. Never two dark sections back-to-back without a light section between them. **Section padding:** `100px 5%` — consistent throughout. Hero: `120px 5% 80px` (accounts for fixed nav). **Max-width container:** `1200px` centered with `margin: 0 auto`. Narrower containers (`1060px`, `1100px`) for CTA and bio sections. ### The Hero Section The hero is always dark (`--blue-dark` background) with the mesh gradient overlay. - Fixed nav: `rgba(47,62,70,0.97)` + `backdrop-filter: blur(8px)` + `border-bottom: 1px solid rgba(255,255,255,0.08)` - Grid layout: left text column + right floating card, `gap: 80px` - Headline: `clamp(38px, 5vw, 62px)`, Playfair 700, white, `letter-spacing: -0.5px` - Subhead: `18px`, DM Sans 300, `rgba(255,255,255,0.65)` - Trust stats bar: `border-top: 1px solid rgba(255,255,255,0.1)`, Playfair numbers in white + `--green-light` accent - Grid texture overlay: `opacity: 0.04`, `background-size: 60px 60px` — adds depth without noise --- ## 3. Typography on Web Same typefaces (Playfair Display + DM Sans) as defined in the Brand Foundation, but with web-specific sizing and behavior. ### Web Type Scale | Role | Family | Size | Weight | Notes | |---|---|---|---|---| | Hero headline | Playfair Display | `clamp(38px, 5vw, 62px)` | 700 | `letter-spacing: -0.5px` | | Section headline | Playfair Display | `clamp(28px, 3.5vw, 44px)` | 700 | | | Card/panel headline | Playfair Display | 24–32px | 700 | | | Section tag / eyebrow | DM Sans | 11px | 700 | `letter-spacing: 2px`, uppercase, `--green` | | Body / section sub | DM Sans | 16–18px | 300 | `line-height: 1.65–1.7` | | Card body | DM Sans | 14–15px | 300–400 | `line-height: 1.6` | | Small labels / captions | DM Sans | 12–13px | 500–600 | | | Disclosure / legal | DM Sans | 11–13px | 300–400 | `rgba(255,255,255,0.25–0.35)` on dark | **Key differences from print:** - Body copy is 16–18px on web (vs. 12–14px in print) — screens require larger type - Line height is 1.65–1.7 on web (vs. 1.60–1.65 in print) - Hero headlines use `clamp()` for responsive scaling — never fixed px on headings - Section eyebrows use `letter-spacing: 2px` (vs. `0.16–0.18em` in print) — web rendering differs --- ## 4. Color Usage on Web All tokens are defined in the **Brand Foundation, Part 5.** This section defines how roles differ from print. ### Orange on web — broader use permitted Unlike print where orange is structural and urgency-specific only, on web orange takes a more active role: - **Primary CTA button:** `background: var(--orange)` — the main call-to-action in the nav and form submit button - **Secondary accent:** Used in pain point blocks (`border-left: 3px solid var(--orange)`) alongside orange label text - **Badge labels:** `color: var(--orange)` in badge chips (e.g., urgency labels) - **Warning/alert states:** `color: var(--orange)` for values that need attention in data displays Orange on web is still not for general body text or decorative purposes. It remains a signal color — but on web it means *primary action* or *attention*, not just *urgency/risk*. ### Green on web - Primary buttons: `background: var(--green)`, hover: `var(--green-hover)` - Links and text accents: `color: var(--green)` - Checkmarks, success states, active indicators - Outline button variant on dark: `border: 1px solid rgba(62,142,99,0.5)`, `color: var(--green-light)` ### `--green-light` on web Used more liberally on dark backgrounds than in print: - Section tags/eyebrows on dark - Hero headline italic accents - Stat numbers in hero trust bar - Card metric values (positive/good states) - Floating card value labels --- ## 5. Buttons and Interactive Elements ### Button Hierarchy **Primary (green)** — main page action, used once per major section: ```css background: var(--green); color: white; padding: 15px 30px; border-radius: 5px; font-size: 15px; font-weight: 600; transition: background .2s, transform .2s; ``` Hover: `background: var(--green-hover); transform: translateY(-2px);` **Primary (orange)** — highest-priority CTA, used in nav and final form submit: ```css background: var(--orange); color: white; padding: 10–15px 22–30px; border-radius: 4–5px; font-weight: 600; transition: opacity .2s, transform .2s; ``` Hover: `opacity: .88; transform: translateY(-2px);` **Outline (on dark)** — secondary option alongside a primary button: ```css background: transparent; color: white; border: 1px solid rgba(255,255,255,0.3); border-radius: 5px; padding: 15px 30px; transition: border-color .2s, background .2s; ``` Hover: `border-color: white; background: rgba(255,255,255,0.06);` **Green outline (on dark)** — alternative secondary for green-accented dark sections: ```css background: transparent; color: var(--green-light); border: 1px solid rgba(62,142,99,0.5); border-radius: 5px; ``` Hover: `background: rgba(62,142,99,0.15); border-color: var(--green-light);` **Button rules:** - Never more than two buttons in a button group - Primary (orange) + outline (white) is the approved pairing for hero - Primary (green) is the approved single-button style in content sections - `border-radius: 4–5px` on all buttons — not 0 (too harsh) and not 8px+ (too rounded) ### Form Inputs (on dark backgrounds) ```css background: rgba(255,255,255,0.07); border: 1px solid rgba(255,255,255,0.12); border-radius: 6px; padding: 12px 14px; color: white; transition: border-color .2s, background .2s; ``` Focus: `border-color: var(--green); background: rgba(62,142,99,0.08);` ### Pill Badges / Chips Permitted on web (explicitly avoided in print): ```css border-radius: 100px; padding: 6–8px 16–18px; font-size: 11–13px; font-weight: 600–700; letter-spacing: 1.2–1.5px; text-transform: uppercase; ``` Three approved variants: - Orange accent: `background: rgba(243,141,12,0.2); color: var(--orange); border: 1px solid rgba(243,141,12,0.3);` - Green accent: `background: rgba(62,142,99,0.15); color: var(--green-light); border: 1px solid rgba(62,142,99,0.3);` - Blue neutral: `background: var(--blue-pale); color: var(--blue-dark);` **Animated pulse badge** (hero eyebrow): ```css background: rgba(62,142,99,0.15); border: 1px solid rgba(62,142,99,0.35); border-radius: 100px; ``` With `::before` pulse dot: `width: 6px; height: 6px; background: var(--green-light); animation: pulse 2s infinite;` --- ## 6. CTA Strategy on Web Unlike print (one CTA per document, at the end), web uses more aggressive and distributed CTA placement. Web visitors are often anonymous and first-time — they have no existing relationship with Brent. The goal is conversion, not just deepened trust. ### Web CTA Placement Pattern - **Navigation:** Orange CTA button always present in fixed nav ("Schedule a Consult" or equivalent) - **Hero section:** Primary action (orange button) + secondary action (outline button) - **After each major content section:** Contextual inline CTA — lighter in intensity, appropriate to the section topic - **Final CTA section:** Full dedicated dark panel with headline, action options, and contact form ### The Three-Option CTA Block The landing page uses a validated pattern for the final CTA: three parallel options in glass cards on a dark gradient panel, each with its own context and button. This acknowledges that different visitors are at different stages: - Urgency option (orange badge): For those ready to act now - Analysis option (green badge): For those who want evidence first - Phone option (blue badge): For those who prefer direct contact **This is a web-only pattern — do not translate it to print.** ### Pain Point Blocks Used within campaign content sections to agitate a problem before presenting a solution: ```css background: #FFF8F0; border-left: 3px solid var(--orange); border-radius: 0 6px 6px 0; padding: 14px 18px; ``` With orange uppercase label above the copy. This is the web equivalent of the print tension block — same structural role, lighter styling. --- ## 7. Navigation Fixed nav with scroll blur: ```css position: fixed; top: 0; left: 0; right: 0; background: rgba(47,62,70,0.97); backdrop-filter: blur(8px); height: 68px; border-bottom: 1px solid rgba(255,255,255,0.08); ``` Nav link color: `rgba(255,255,255,0.72)` → white on hover, `transition: color .2s` Phone number: ghost button style with `border: 1px solid rgba(255,255,255,0.15)` → brightens on hover Primary CTA: orange button — the only orange button in the nav. --- ## 8. What Print Has That Web Doesn't For completeness — these elements are print-specific and should not appear on web: | Print Element | Web Equivalent | |---|---| | Orange left-edge rule (structural panel signature) | Left border on pain point block (`border-left: 3px solid --orange`) | | Footer bar with document title + page number | HTML `<footer>` with logo + legal text | | Disclosure strip (FINRA/SIPC) | Footer legal text `11px rgba(255,255,255,0.25)` | | Three-column ruled layout | CSS grid with `gap` — no visible column dividers | | Full-bleed panel system | Full-width sections with `padding: 100px 5%` | | DM Sans 300 body copy at 12–13px | DM Sans 300 body copy at 16–18px | | Single CTA per document | Multiple CTAs — nav, hero, sections, final panel | | Background glyph (Playfair character) | Not used on web | --- ## 9.
